# PokeMMO 孵蛋助手（只读 OCR）

这是一个 Windows 本地素材库存与孵蛋规划工具，目标是把“你手动点击精灵”和“程序识别、保存、规划”分开：

- 你手动在 PokeMMO 中点击仓库格子和切换仓库页；
- 程序只截取当前可见窗口或读取截图；
- OCR 提取当前精灵的名字、性别、六项个体值、性格、最多四个技能和头目（Alpha）图标；蛋组根据名字从内置资料库自动补全；
- 支持连续录入：首次画面稳定后自动 OCR；每次按回车确认入库后默认显示 3.00 秒倒计时（可在 1.5–8 秒间调整），到点强制 OCR 当前可见画面，适合录入数百至上千只素材；
- 单窗口支持自由缩放：窄窗口自动使用上下布局，宽窗口自动恢复左右布局，预览、列表和文本区会随窗口调整；
- 结果保存到本地 SQLite 库存；连续扫描必须按回车人工确认，单张 OCR 也可修正后保存；
- 内置 1–649 号物种的中英文名称、蛋组、性别比例和幼体标记；
- 规划前先统计同进化线、同蛋组与百变怪（可选）库存，并按目标 IV 档位汇总；优先复用高 V 素材、保护不应降级消耗的高价值素材，仅在库存无法严格完成时列出交易行补购规格；
- 目标性格默认采用“后置性格”：例如 5V 固执按 5V 随机性格主线 + 4V 固执支线合成，最终一步使用不变石；也可切换为全程不变石链。未锁性格的中间节点会记录是否随机爆出目标性格，命中后可立即按最新库存重算；
- 成品性别与中间过程性别分开设置：默认“智能锁定”让低 V 第一支随机孵出，记录实际性别后只锁配对所需的另一支；5V、指定成品性别和艾路雷朵/蜂女王等性别限定进化目标保持确定。也可切换为“全程锁定”或“尽量不锁”，并对当前下一步单独选择自动、不锁、锁母或锁公；
- 按进化线理解目标种类：例如龙王蝎路线会同时利用钳尾蝎与龙王蝎素材，并把实际孵出的钳尾蝎、后续进化要求显示在路线树中；无性别精灵可使用同进化线素材或百变怪；
- 路线以可缩放、可平移的思维导图显示；目标在顶部，父母分支向下展开。每个孵化节点同时显示“是否完成”和“是否爆性格”，可按顺序勾选，确认后原子核销两只父母并加入该步子代，且支持撤销最近一次核销。
- 思维导图中的真实库存叶节点支持“本次禁用”：可临时保护节日头目、纪念素材等不想消耗的精灵并立即重算替代路线；素材不会从库存删除，同一孵化目标下可连续排除多只，也可点击“恢复全部并重算”。切换到其他孵化进化线或重启工具后，本次排除自动清空。
- 普通有性别精灵遵循母系出种：目标进化线雌性负责产出目标蛋，任意同蛋组雄性可作为父本；其他同组雌性只会在能先产出有价值雄性中转素材时进入路线。交易行雄性缺料按“蛋组兼容雄性”列出，不再强制购买目标物种。
- 单性别素材按实际孵出形态处理：幸福蛋、迷唇姐等无法产出雄性后代的纯母进化线，只在孵自身目标时作为母系使用，不会再进入其他物种的中转链；肯泰罗、飞腿郎等纯公精灵仍可作为同蛋组通用父本。纯公目标本身仍需按百变怪路线孵化。
- 库存素材按真实 V 数进入孵化链：2V 必须从 2V 节点起步，3V 必须从 3V 节点起步；规划器不会再把高 V 素材降级塞进 1V/2V 子问题。若素材的额外 31 位于目标的 `X` 项，该素材会保留在库存而不是被浪费。
- 头目路线以 2V 为最低素材层：交易行缺料和性格素材均从互补 2V 头目开始，不生成 1V 头目叶子，再按 2V → 3V → 4V → 5V 合成。
- 普通目标默认只使用普通素材，保护头目库存；在“高级规则”中可显式允许普通目标使用头目素材。开启后普通与头目库存都可参与，但最终子代仍严格为普通；头目目标始终只使用头目素材。
- 输入大嘴蝠、叉字蝠等高级形态时，规划树的孵蛋目标统一显示实际孵出的第一形态（超音蝠），所选高级形态只作为孵化后的进化目标保留。

程序不会发送键盘/鼠标输入，不会读取 PokeMMO 内存，不会抓取网络，也不会修改游戏客户端。

## 运行

新电脑首次使用：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./setup.ps1
python app.py
```

OCR 依赖当前要求 Python 3.10–3.12；`setup.ps1` 会优先寻找 3.12、3.11、3.10，并拒绝不兼容的 3.13+，避免下载到一半才失败。

如果电脑同时安装了多个 Python，可以指定解释器：

```powershell
./setup.ps1 -Python 'C:\Path\to\python.exe'
./build.ps1 -Python 'C:\Path\to\python.exe'
```

`setup.ps1` 会把 OCR 和打包依赖安装到项目自己的 `vendor/` 目录；该目录被 Git 忽略，不需要上传。

## 推荐工作流

1. 启动 PokeMMO，打开仓库；在工具中点击“刷新窗口”，选择 PokeMMO 窗口，再点“连接并实时预览”。预览会按窗口句柄持续刷新，PokeMMO 移动或缩放后无需重新获取。
2. 工具连接窗口时会默认选择左侧信息面板作为 OCR 区域；如当前主题布局不同，可重新框选，需包含左上角头目图标、名字/性别、“个体值”、“性格”、“标记”和下方技能区域。工具窗口可直接拖动边框自由缩放。
3. 在连续扫描区填写起始箱、起始格和每箱格数，点击“开始连续扫描”。
4. 首次画面稳定后，工具会把 OCR 结果显示在右侧并把键盘焦点切回助手，但不会自动保存。核对名字、性别和六项 IV 后按回车，记录才会写入当前箱/格并自动前进一格；随后摘要右侧按“切换等待”开始倒计时（默认 3 秒，可调 1.5–8 秒），请在到点前手动选择下一只，到点后工具会强制截图并 OCR。复核会同时检查稳定文字区域和 OCR 字段变化；若连续两只可见资料完全相同，可点“识别当前精灵”强制按新素材录入。遇到空格可点“跳过一格”。
5. 在“素材库存”里检查已确认记录。按同一箱号/格号重新扫描会更新该位置，不会添加重复库存。
6. 在“孵蛋规划”中输入图鉴编号或中英文名字片段，从候选列表双击目标精灵，并选择普通或头目；蛋组、性别比例、实际孵出形态和中间代进化要求会自动填充。目标性格提供 20 种属性修正性格和一个“无修正（任一）”，六项目标 IV 分格填写，留空或 X 表示任意。“查看分布与遗传技能”可查看参考表中的地点和可行技能链。
7. 生成方案后先查看“库存预检”和依赖树。高级规则中的“中间性别”默认使用智能锁定；启用方案后，当前步骤上方可临时改为自动、不锁、锁母或锁公。即使路线后段有缺料，也可先完成蓝色库存节点；点击当前节点的复选格（或“完成下一步并核销父母”）会原子地删除两只父母并加入子代。
8. 不锁性别的节点完成时，工具会要求记录实际孵出的公/母；未使用不变石时还会询问是否爆出目标性格。实际结果保存进库存后，剩余路线会自动重算。走到橙色缺料节点时，手动取得素材并 OCR 扫描入库，再重新生成方案。
9. 若误点核销，可点击“撤销上一次核销”。

程序不会自动点击格子或翻页；这是为了把输入控制留在你手中，降低触发游戏规则风险。连续扫描只使用可见屏幕截图，F8 也只在助手获得焦点时重新启动本地倒计时，不会向游戏发送按键，因此工具窗口应放在游戏窗口外侧。OCR 置信度只用于提示，不再决定是否自动保存；所有连续扫描记录都必须由你按回车确认。

手动加载或截取一张新图片后，“保存”会新增一只素材；只有先在库存列表中主动选中某条记录，按钮才会进入更新模式。连续扫描则按箱号/格号更新同一位置，避免重复扫描同一格时生成重复库存。

PokeMMO 官方明确禁止自动输入、宏、脚本和自动点击器。本项目不会向游戏发送输入，但这不构成官方许可或封号保证；规则发生变化时应以 [PokeMMO Macroing FAQ](https://support.pokemmo.com/knowledgebase/article/macroing-faq) 和 [Code of Conduct](https://pokemmo.com/en/code_of_conduct/) 为准。

## 测试

规划器不依赖 OCR，可以单独运行测试：

```powershell
python -m unittest discover -s tests -v
```

测试覆盖直接配对、跨两代链路、中文“百变怪”、无性别同进化线孵化、实际幼体形态、性格遗传、智能/全程/最少锁性别策略、性别限定进化、普通/头目继承、5V 标准金字塔、5V + 性格金字塔、高价值素材保护、素材不重复使用、跨物种蛋组素材、未核对记录隔离、精确缺料、方案执行与原子核销/撤销。

## 生成 EXE

开发和排查问题时使用目录版：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./build.ps1
```

生成目录位于 `dist/PokeMMO-Breeder-Helper/`，入口是同名 EXE。目录版便于检查 OCR 模型和依赖。

如果需要排查启动错误，可以临时使用 `./build.ps1 -Console` 生成带控制台的调试版本。

给普通用户发布时使用单文件发布脚本：

```powershell
./release.ps1
```

脚本会生成 `release/Pokemmo孵蛋助手-晨若.exe`，并把 EXE、使用说明、第三方声明和 SHA-256 校验值打包为 `release/Pokemmo孵蛋助手-晨若-发布包.zip`。OCR 模型、离线物种资料和界面素材均内置，不要求接收者安装 Python。单文件版首次启动需要解压内置组件，启动时间通常比目录版稍长。

单文件打包可以防止普通用户直接看到或随意改动单个源码/数据文件，但不是加密或绝对防逆向。正式公开发布前，建议再为 EXE 添加可信的 Windows 数字签名；如果源代码仓库仍为公开状态，打包本身不能保护已经公开的源代码。

库存数据库默认保存到：

```text
%LOCALAPPDATA%\PokeMMO-Breeder-Helper\inventory.db
```

旧版 `inventory.json` 会在首次启动时自动迁移。JSON 导入/导出仍可用于备份和交换数据。执行中的方案保存在同目录的 `active_plan.json`，父母核销历史保存在 SQLite 数据库中。

## 内置物种资料

`data/species.json` 由 `scripts/build_species_data.py` 从 [PokeAPI/pokeapi](https://github.com/PokeAPI/pokeapi) 的公开 CSV 生成，包含 1–649 号物种的简繁中文/英文名称、蛋组、性别比例和幼体标记。PokeMMO 特有差异单独放在 `data/pokemmo_overrides.json`，便于审查和更新，不需要读取客户端内存。

## 当前限制

- 六项 IV 都填写时会按完整六项精确路线规划；例如 `31/31/31/0/31/31` 与 `31/31/31/16/31/31` 都采用 6V 同层级的孵化树，同时保留非 31 项的准确数值；
- 思维导图节点内置离线精灵缩略图和本步护腕/不变之石图标；`31`、`X` 与 `0–30` 精确值同时使用不同底色和明确数字区分，颜色不是唯一提示；运行时不会联网取图，也不会读取或解包 PokeMMO 客户端；
- 连续扫描依赖当前主题、分辨率和框选区域；字段不完整时必须先人工修正，回车确认后才会进入库存；
- 个体值通过“个体值”标签及其水平位置定位，不会把上方能力值或下方努力值写入库存；透明主题中 OCR 合并绿色 6V 文本时，只在检测到六个等距满 IV 绿色文本簇后恢复为 6×31；性别同时检查文字和名字行附近的粉/蓝色符号；
- 性格通过“性格”标签定位并规范为 PokeMMO 中文名；技能只读取“标记”下方最多四行，并使用第 1–5 世代公开技能名词典及已审查 OCR 别名纠错；
- 头目属性通过左上角红色 Alpha 图标识别，并可在保存前人工改为“普通/头目”；根据 [PokeMMO 管理员说明](https://forums.pokemmo.com/index.php?/topic/147290-can-you-breed-alpha-mons/)，只有头目×头目才保留头目属性，头目×普通得到普通子代，因此规划器会逐代检查两只父母；
- 连续两只素材的可见信息完全相同时，工具可能无法仅凭信息面板判断已经切换；请使用“重新识别当前精灵”；
- 自动位置递增假设你按顺序扫描；遇到空格或跳号时需要使用“跳过一格”或手动修改箱/格；
- 物种资料以 PokeAPI 为基础，并预留 PokeMMO 差异覆盖；发现游戏内差异时应在覆盖文件中记录来源后修正；
- 地点与技能链来自用户提供的 `全地区精灵分布.xlsx` 和 `技能遗传链.xlsx`；当前导入 4,441 条分布记录和 11,145 条技能链；
- 蛋招式、隐藏特性、闪光、OT、精灵球和服装暂未加入严格规划；普通/头目属性已经加入严格规划；
- 需要熏香才能孵出的幼体会被明确拦截，因为熏香会与护腕/不变之石争用携带道具位；在该冲突完成严格建模前，工具不会生成看似可行但实际错误的路线；
- 护腕按 10,000/个统计固定费用；不变之石市价和不同性别比例的指定费用只统计次数，不硬编码为固定价格；
- 核销按钮只修改本地数据库；用户仍需自己在游戏中完成孵化，工具不会发送输入。
