# PokeMMO 孵蛋助手（只读 OCR）

这是一个 Windows 本地素材库存与孵蛋规划工具，目标是把“你手动点击精灵”和“程序识别、保存、规划”分开：

- 你手动在 PokeMMO 中点击仓库格子和切换仓库页；
- 程序只截取当前可见窗口或读取截图；
- OCR 提取当前精灵的名字、性别、六项个体值、性格、当前特性、最多四个技能、头目（Alpha）图标和特性行的梦特蓝钻；蛋组根据名字从内置资料库自动补全；
- 支持连续录入：首次画面稳定后自动 OCR；每次按回车确认入库后默认显示 3.00 秒倒计时（可在 1.5–8 秒间调整），到点强制 OCR 当前可见画面。保存后的下一格为空时，可在倒计时或 F8 待重试状态按 Space，只推进逻辑仓位而不写入库存；
- 单窗口支持自由缩放：窄窗口自动使用上下布局，宽窗口自动恢复左右布局，预览、列表和文本区会随窗口调整；
- 结果保存到本地 SQLite 库存；连续扫描必须按回车人工确认，单张 OCR 也可修正后保存；
- 内置 1–649 号物种的中英文名称、蛋组、性别比例和幼体标记；
- 规划前先统计同进化线、同蛋组与百变怪（可选）库存，并按目标 IV 档位汇总；勾选百变怪后会优先采用可行的库存百变怪路线；优先复用高 V 素材、保护不应降级消耗的高价值素材，仅在库存无法严格完成时列出交易行补购规格；
- 目标性格默认采用“后置性格”：例如 5V 固执按 5V 随机性格主线 + 4V 固执支线合成，最终一步使用不变石；也可切换为全程不变石链。未锁性格的中间节点会记录是否随机爆出目标性格，命中后可立即按最新库存重算；
- 成品性别与中间过程性别分开设置：母体主线持续锁母，直接并入母体的普通素材支线锁公；若某个子代下一步直接与百变怪孵化，则本路线无需确认其性别，也不会为此重算路线。也可切换“全程锁定”或“尽量不锁”，并对当前下一步单独选择自动、不锁、锁母或锁公；
- “仅用百变怪转换母体”与“优先使用库存百变怪”相互独立：库存没有目标母体但有目标公体时，可只用一次公体＋百变怪锁母建立母系，其余支线继续禁用百变怪；若目标公母都没有，则直接采购目标母体，库存优先从最低实用档开始，步骤优先可采购较高 V 母体；
- 按进化线理解目标种类：例如龙王蝎路线会同时利用钳尾蝎与龙王蝎素材，并把实际孵出的钳尾蝎、后续进化要求显示在路线树中；无性别精灵可使用同进化线素材或百变怪；
- 路线以可缩放、可平移的思维导图显示；目标在顶部，父母分支向下展开，也可放到独立最大化窗口查看。节点的个体值档位统一显示为 `1V`、`2V`、`3V` 等阿拉伯数字格式。已完成节点默认折叠被消耗的来源，双击可展开/收起历史；可对多个并行节点双击或点按钮标记“孵化中”。互不依赖的同层分支可并行、任意顺序勾选，只有直接父子依赖会阻止上层提前核销。确认后原子核销两只父母；中间代写入素材库存继续参与路线，最终成品只完成核销而不再入库。撤销最近一次核销会恢复当时的步骤、依赖和完整路线快照。
- 逐级赌性格重算时会保留完整阶段语境：5V 母体未命中后，思维导图仍显示这只已保留母体与正在制作的 4V 性格手；4V 再次未命中并转入 3V 后，也会继续显示已保留的 4V 素材。阶段预览节点只用于说明后续合成，不会重复核销库存。
- 孵蛋规划可严格要求“保留梦特潜力”和最多四个遗传技能。头目素材默认标记梦特潜力已解锁；普通素材的自动梦特认证只看特性行旁的蓝色钻石，不再要求或参考字体是否为金色，也可在库存编辑器中人工勾选。梦特只从目标孵出进化线上的梦特父母传递，不会把其他同蛋组雄性的梦特错误套到目标后代；遗传技能先搜索库存中真正携带该技能的兼容父本，缺失时再按工作簿中的实际物种列出交易行补购。技能首次导入目标进化线的孵化节点会显示红色粗边框和“遗传技能导入”文字。
- 思维导图中的真实库存叶节点支持“本次禁用”：可临时保护节日头目、纪念素材等不想消耗的精灵并立即重算替代路线；素材不会从库存删除，同一孵化目标下可连续排除多只，也可点击“恢复全部并重算”。切换到其他孵化进化线或重启工具后，本次排除自动清空。
- 普通有性别精灵遵循母系出种：目标进化线雌性负责产出目标蛋，任意同蛋组雄性可作为父本；其他同组雌性只会在能先产出有价值雄性中转素材时进入路线。交易行雄性缺料按“蛋组兼容雄性”列出，不再强制购买目标物种。
- 单性别素材按实际孵出形态处理：幸福蛋、迷唇姐等无法产出雄性后代的纯母进化线，只在孵自身目标时作为母系使用，不会再进入其他物种的中转链；肯泰罗、飞腿郎等纯公精灵仍可作为同蛋组通用父本。纯公目标本身仍需按百变怪路线孵化。
- 尼多家族按 PokeMMO 的特殊子代规则单独处理，不套用普通纯公限制：孵尼多王时以尼多兰/尼多娜/尼多后作为母体主线，中间层持续锁母并接收怪兽组或陆上组雄性素材，只有成品层锁公孵出尼多朗后再进化；库存缺少母体或父本时照常列出交易行补购，不会再得到“无可执行方案”。
- 库存素材按真实 V 数进入孵化链：2V 必须从 2V 节点起步，3V 必须从 3V 节点起步；规划器不会再把高 V 素材降级塞进 1V/2V 子问题。若素材的额外 31 位于目标的 `X` 项，该素材会保留在库存而不是被浪费。
- 头目路线以 2V 为最低素材层：交易行缺料和性格素材均从互补 2V 头目开始，不生成 1V 头目叶子，再按 2V → 3V → 4V → 5V 合成。
- 普通目标默认只使用普通素材，保护头目库存；在“高级规则”中可显式允许普通目标使用头目素材。开启后普通与头目库存都可参与，但最终子代仍严格为普通；头目目标始终只使用头目素材。
- 输入大嘴蝠、叉字蝠等高级形态时，规划树的孵蛋目标统一显示实际孵出的第一形态（超音蝠），所选高级形态只作为孵化后的进化目标保留。
- 顶部提供“扫描素材”“孵蛋规划”“作者的话”三个工作区；“作者的话”固定在最右侧，进入规划或作者页面后会隐藏画面来源、连续扫描和实时预览，把空间留给当前内容。作者页面只保留紧凑说明和支付宝、微信收款码入口。实时预览可双击打开独立放大框选器，并支持滚轮缩放、中键平移和左键精确框选。
- 库存支持“账号/角色”维度和账号筛选；“当前账号”旁的 `+` 可新建小号，空账号名称也会持久保存。扫描仍按“第几页/第几格”递增，库存表和路线节点则统一换算为 `页-行,列`，例如第 5 页第 13 格显示为 `5-2,3`；旧库存会在读取时直接以新坐标显示。位置只是上次已知位置，不作为素材的永久身份。

程序不会发送键盘/鼠标输入，不会读取 PokeMMO 内存，不会抓取网络，也不会修改游戏客户端。

## 运行

新电脑首次使用：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./setup.ps1
python app.py
```

OCR 依赖当前要求 Python 3.10–3.12；`setup.ps1` 会优先寻找 3.12、3.11、3.10，并拒绝不兼容的 3.13+，避免下载到一半才失败。

如果电脑同时安装了多个 Python，可以指定解释器：

```powershell
./setup.ps1 -Python 'C:\Path\to\python.exe'
./build.ps1 -Python 'C:\Path\to\python.exe'
```

`setup.ps1` 会把 OCR 和打包依赖安装到项目自己的 `vendor/` 目录；该目录被 Git 忽略，不需要上传。

## 推荐工作流

1. 启动 PokeMMO，打开仓库；在工具中点击“刷新窗口”，选择 PokeMMO 窗口，再点“连接并实时预览”。预览会按窗口句柄持续刷新，PokeMMO 移动或缩放后无需重新获取。
2. 工具连接窗口时会默认选择左侧信息面板作为 OCR 区域；如当前主题布局不同，可重新框选，需包含左上角头目图标、名字/性别、“个体值”、“性格”、“标记”和下方技能区域。工具窗口可直接拖动边框自由缩放。
3. 在连续扫描区填写当前账号/角色、起始箱、起始格和每箱格数；需要小号时点账号右侧 `+` 新建。旧电脑可把“OCR 负载”切为“省资源”，它只限制 CPU 线程和预览刷新频率，不更换识别模型。然后点击“开始连续扫描”。
4. 首次画面稳定后，工具会把 OCR 结果显示在右侧并把键盘焦点切回助手，但不会自动保存。核对名字、性别和六项 IV 后按回车，记录才会写入当前箱/格并自动前进一格；随后摘要右侧按“切换等待”开始倒计时（默认 3 秒，可调 1.5–8 秒）。如果这个“下一格”为空，直接按 Space 或点录入节奏卡底部的“下一格为空：跳过”；倒计时期间以及出现 F8 待重试提示后都可使用。工具仅将逻辑位置前进一格、重开倒计时，不会往素材库加入空记录。可连续按 Space 跳过多个空格。到点后工具会强制截图并 OCR；若连续两只可见资料完全相同，可点“识别当前精灵”强制按新素材录入。
5. 在“素材库存”里检查已确认记录。双击一行可编辑名字、性格、当前特性、技能、梦特潜力、账号和上次仓位；`Ctrl/Shift + 单击`可多选，支持全选当前筛选结果、批量删除及撤销最近一次删除。名字、性格、特性与逗号分隔技能均提供本地候选。账号相同且同一仓位再次出现同一只可见素材时会更新记录；出现不同素材时不会删除旧库存，只会把旧记录标为位置未记录。
6. 切换到“孵蛋规划”工作区，输入图鉴编号或中英文名字片段，从候选列表双击目标精灵，并选择普通或头目；蛋组、性别比例、实际孵出形态和中间代进化要求会自动填充。目标性格窗口可直接输入中文或英文实时筛选，例如输入“固”会立即显示“★ 固执”；六项目标 IV 分格填写，留空或 X 表示任意。可勾选“成品保留梦特”，并在“选择遗传技能”中选择最多四项。
7. 生成方案后目标表单和长说明会自动收起，让思维导图占据主要空间；“修改目标与查看说明”展开后，同一位置会变成“收起目标与说明”，可随时收回。也可点击“独立查看路线”。高级规则中的“中间性别”默认使用智能锁定；启用方案后，选择任一当前可执行节点可临时改为自动、不锁、锁母或锁公。如果同时孵多组蛋，可双击节点或点“标记孵化中”作为备忘；重启后仍保留，完成核销时自动清除。即使路线后段需要补购，也可先并行完成多个蓝色库存节点；实际性别或爆性格改变路线时，工具会按最新库存自动重算并尽量保留仍匹配的“孵化中”节点。
8. 不锁性别的节点完成时，工具会要求记录实际孵出的公/母；未使用不变石时还会询问是否爆出目标性格。需要继续参与路线的中间结果会保存进库存并自动重算。橙色交易行素材按规划购买即可，无需 OCR 扫描入库；确认对应孵化节点完成时，工具会直接视为已使用。最终成品完成后只核销真实库存父母，不会把成品加入素材库存。
9. 若误点核销，可点击“撤销上一次核销”。

程序不会自动点击格子或翻页；这是为了把输入控制留在你手中，降低触发游戏规则风险。连续扫描只使用可见屏幕截图，F8 也只在助手获得焦点时重新启动本地倒计时，不会向游戏发送按键，因此工具窗口应放在游戏窗口外侧。OCR 置信度只用于提示，不再决定是否自动保存；所有连续扫描记录都必须由你按回车确认。

手动加载或截取一张新图片后，“保存”会新增一只素材；只有先在库存列表中主动选中某条记录，按钮才会进入更新模式。连续扫描会结合账号、上次箱位和可见素材字段更新记录；仓位变化本身不会删除素材。

PokeMMO 官方明确禁止自动输入、宏、脚本和自动点击器。本项目不会向游戏发送输入，但这不构成官方许可或封号保证；规则发生变化时应以 [PokeMMO Macroing FAQ](https://support.pokemmo.com/knowledgebase/article/macroing-faq) 和 [Code of Conduct](https://pokemmo.com/en/code_of_conduct/) 为准。

规划器不依赖 OCR，可以单独运行测试：

```powershell
python -m unittest discover -s tests -v
```

测试覆盖直接配对、跨两代链路、中文“百变怪”、无性别同进化线孵化、实际幼体形态、性格遗传、智能/全程/最少锁性别策略、性别限定进化、普通/头目继承、5V 标准金字塔、5V + 性格金字塔、高价值素材保护、素材不重复使用、跨物种蛋组素材、未核对记录隔离、精确缺料、方案执行与原子核销/撤销。

## 生成 EXE

开发和排查问题时使用目录版：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
./build.ps1
```

生成目录位于 `dist/PokeMMO-Breeder-Helper/`，入口是同名 EXE。目录版便于检查 OCR 模型和依赖。

如果需要排查启动错误，可以临时使用 `./build.ps1 -Console` 生成带控制台的调试版本。

给普通用户发布时使用单文件发布脚本：

```powershell
./release.ps1
```

脚本会生成 `release/Pokemmo孵蛋助手-晨若.exe`，并把 EXE、使用说明、第三方声明和 SHA-256 校验值打包为 `release/Pokemmo孵蛋助手V0.19.zip`。后续发布时继续递增版本号即可。OCR 模型、离线物种资料和界面素材（包括作者提供的收款码）均内置，不要求接收者安装 Python。单文件版首次启动需要解压内置组件，启动时间通常比目录版稍长。

单文件打包可以防止普通用户直接看到或随意改动单个源码/数据文件，但不是加密或绝对防逆向。正式公开发布前，建议再为 EXE 添加可信的 Windows 数字签名；如果源代码仓库仍为公开状态，打包本身不能保护已经公开的源代码。

库存数据库默认保存到：

```text
%LOCALAPPDATA%\PokeMMO-Breeder-Helper\inventory.db
```

旧版 `inventory.json` 会在首次启动时自动迁移。JSON 导入/导出仍可用于备份和交换数据。执行中的方案保存在同目录的 `active_plan.json`，父母核销历史保存在 SQLite 数据库中。

## 内置物种资料

`data/species.json`、`data/moves.json` 和 `data/abilities.json` 分别由对应构建脚本从 [PokeAPI/pokeapi](https://github.com/PokeAPI/pokeapi) 的公开 CSV 生成，覆盖 1–649 号物种的名称、蛋组、性别比例、技能名以及普通/隐藏特性名称。PokeMMO 特有差异单独放在 `data/pokemmo_overrides.json`，便于审查和更新，不需要读取客户端内存。

## 当前限制

- 六项 IV 都填写时会按完整六项精确路线规划；例如 `31/31/31/0/31/31` 与 `31/31/31/16/31/31` 都采用 6V 同层级的孵化树，同时保留非 31 项的准确数值；
- 思维导图节点内置离线精灵缩略图；每只父母节点只显示它自己携带的一件护腕或不变之石，符合游戏中“一只精灵一个持有道具”的规则。`31`、`X` 与 `0–30` 精确值同时使用不同底色和明确数字区分，颜色不是唯一提示；运行时不会联网取图，也不会读取或解包 PokeMMO 客户端；
- 连续扫描依赖当前主题、分辨率和框选区域；字段不完整时必须先人工修正，回车确认后才会进入库存；
- 个体值通过“个体值”标签及其水平位置定位，不会把上方能力值或下方努力值写入库存；透明主题中 OCR 合并绿色 6V 文本时，只在检测到六个等距满 IV 绿色文本簇后恢复为 6×31；性别同时检查文字和名字行附近的粉/蓝色符号；
- 性格通过“性格”标签定位并规范为 PokeMMO 中文名；技能只读取“标记”下方最多四行，并使用第 1–5 世代公开技能名词典及已审查 OCR 别名纠错；
- 头目属性通过左上角红色 Alpha 图标识别，并可在保存前人工改为“普通/头目”；根据 [PokeMMO 管理员说明](https://forums.pokemmo.com/index.php?/topic/147290-can-you-breed-alpha-mons/)，只有头目×头目才保留头目属性，头目×普通得到普通子代，因此规划器会逐代检查两只父母；
- 连续两只素材的可见信息完全相同时，工具可能无法仅凭信息面板判断已经切换；请使用“重新识别当前精灵”；
- 自动位置递增假设你按顺序扫描；遇到空格时按 Space 或点“跳过空位”，遇到大段跳号仍可手动修改箱/格；
- 物种资料以 PokeAPI 为基础，并预留 PokeMMO 差异覆盖；发现游戏内差异时应在覆盖文件中记录来源后修正；
- 地点与技能链来自用户提供的 `全地区精灵分布.xlsx` 和 `技能遗传链.xlsx`；当前导入 4,441 条分布记录和 11,145 条技能链；
- 遗传技能和梦特潜力已加入严格规划；库存技能父本优先、缺失时按工作簿物种补购，并标出首次导入节点，但不会自动模拟招式栏被新技能覆盖，执行前仍应核对四个技能位；
- 梦特 OCR 以特性行旁的蓝色钻石作为唯一自动认证，不再参考特性字体颜色，也不会只凭特性名称猜测；若主题、缩放或裁切导致图标不可见，仍需在库存编辑器人工勾选。头目默认勾选。内置特性名称来自 PokeAPI，PokeMMO 版本差异仍需通过可审查覆盖修正；
- 闪光、OT、精灵球和服装尚未加入严格规划；
- 需要熏香才能孵出的幼体会被明确拦截，因为熏香会与护腕/不变之石争用携带道具位；在该冲突完成严格建模前，工具不会生成看似可行但实际错误的路线；
- 护腕按 10,000/个统计固定费用；不变之石市价和不同性别比例的指定费用只统计次数，不硬编码为固定价格；
- 核销按钮只修改本地数据库；用户仍需自己在游戏中完成孵化，工具不会发送输入。
