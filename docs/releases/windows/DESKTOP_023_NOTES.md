# 电脑端 V0.2.3：策略候选修正

## 范围与升级

本轮只改共享规划逻辑和桌面版本/说明，不改变JSON、执行存档或核销交互。不删除“预览新建议（只读）”。旧执行树不会因替换EXE自动改变：需要生成新建议并确认启用，勿重复核销现实中已经消耗的素材。

修改前已在本地备份完整源码（含此前未提交改动）和桌面发布目录。用户库存仅用副本复算；按后续授权上传电脑端源码，测试数据不上传，不打包APK。已发布Android 0.4.2不包含本次修改。

## 改动

- 库存性格手不再只依赖市场兜底搜索的前两个分支；先搜索实际库存所有IV拆分及同组跨种中转，再对完整性格手排序。允许1V合成2V后接已有2V。
- 不再按物种排序截掉后面的性格手母系；双蛋组可作为中转，独立性格手也可制造同线公亲本。
- 步骤优先按当前阶段构造高V采购亲本：4V随机手可用互补3V亲本孵一次，3V随机手可用互补2V亲本孵一次。库存亲本仍与采购亲本一起比较，不强制全买。
- 快捷候选必须以真实孵化节点结束，不能直接买最终成品；保留随机手阶段、母体、已赌失败的素材及最低保底规则。
- 使用原有IV、身份、性别、头目、梦特与技能约束；等价采购副本去重但不合并不同个体的采购数量。

搜索边界：小库存子问题（至多12个有效叶节点）保留去重后的全部候选；大库存继续使用有界候选搜索与缓存，本轮没有无条件扩大原搜索宽度。市场递归兜底仍是有界启发式，不承诺任意大库存的全局最优。下述穷举结论仅针对明确列出的升V模型与步数范围。

### 库存优先的具体路线

1. 钳尾蝎母（攻击1V）＋太古羽虫公（HP1V）→HP/攻击2V钳尾蝎母。
2. 上一步＋摇篮百合公（攻击/特防2V）→HP/攻击/特防3V钳尾蝎母。
3. 肋骨海龟母（攻击/速度2V）＋信使鸟公（HP/速度2V）→HP/攻击/速度3V原盖海龟公。
4. 两只3V合成HP/攻击/特防/速度4V钳尾蝎公，判断是否爆固执。原5V飞天螳螂母体继续保留。

### 步骤优先的具体路线

采购虫组可孵化母素材（HP/攻击/特防3V）和兼容公素材（HP/攻击/防御3V），分别锁特防与防御，一次孵出HP/攻击/防御/特防4V公性格手。两只采购个体分别计数，性格仍为随机；未爆固执继续下一档，不会被当作成品。

## 刺尾虫结论

的防御/特防2V母刺尾虫**可以使用**，无需先有现成2V公亲本。例如以下零采购路线：

1. 攻击1V钳尾蝎母＋特防1V菊石兽公→攻击/特防2V钳尾蝎公（水中3配对）。
2. 该公亲本＋用户的防御/特防2V刺尾虫母→攻击/防御/特防3V刺尾虫母（虫组配对）。
3. 攻击1V龙王蝎母＋HP1V太古羽虫公→HP/攻击2V钳尾蝎母。
4. 上一步＋攻击/特防2V摇篮百合公→HP/攻击/特防3V钳尾蝎公。
5. 两只3V→HP/攻击/防御/特防4V刺尾虫公，可作为飞天螳螂的同组性格手。

这条路线使用6只不同库存、5次孵化；默认另一条零采购路线只用4次，故不会为了消耗指定刺尾虫而增加一步。不能把“不是默认最优候选”解释为“该素材不能使用”。

另用独立的自底向上枚举核查当前普通库存：按等档互补、锁两项升1档、精确IV档位、不重复用素材，枚举全部5种目标4V组合、最多6个库存叶子（5次孵化），验证零采购4次路线存在，包含这只刺尾虫的最短路线为5次。该枚举不涵盖主动降V或未发生的随机额外31。
